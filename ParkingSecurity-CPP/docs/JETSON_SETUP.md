# Jetson Orin Nano — Dev Environment

How to set up a Jetson Orin Nano for developing the native C++ parking
security system.

## Flash JetPack 6.2+

Use the NVIDIA SDK Manager on a host Ubuntu machine, or manually via the
flash utility. Target:

- **OS**: Ubuntu 22.04 (shipped as L4T R36.4.x)
- **CUDA**: 12.6
- **TensorRT**: 10.3+
- **cuDNN**: 9.3+
- **VPI**: 3.x (optional, for hardware-accelerated CV on Jetson)

Verify after flash:

```bash
cat /etc/nv_tegra_release            # R36 (release), REVISION: 4.x
/usr/local/cuda/bin/nvcc --version
dpkg -l | grep nvinfer
```

## Enable MAXN Super Power Mode

Default is 15W. For face recognition workloads, you want MAXN Super (no
thermal throttle):

```bash
sudo nvpmodel -q                    # Shows current mode
sudo nvpmodel -p --all              # Lists all modes; MAXN_SUPER is mode 2 on Orin Nano Super
sudo nvpmodel -m 2                  # Set to MAXN Super
sudo jetson_clocks                  # Peg clocks at max
```

Persist across reboots: create `/etc/systemd/system/jetson-maxn.service`:

```ini
[Unit]
Description=Set Jetson to MAXN Super power mode
After=multi-user.target

[Service]
Type=oneshot
ExecStart=/usr/sbin/nvpmodel -m 2
ExecStart=/usr/bin/jetson_clocks

[Install]
WantedBy=multi-user.target
```

Then `sudo systemctl enable --now jetson-maxn`.

## DeepStream SDK Installation

DeepStream is NVIDIA's production framework for AI video analytics. Not
strictly required (we can fall back to raw GStreamer) but recommended for
the lowest latency.

1. Register at https://developer.nvidia.com/deepstream-sdk
2. Download the `.deb` for your JetPack version (e.g., `deepstream-7.1_7.1.0-1_arm64.deb`)
3. Install:

```bash
sudo apt install ./deepstream-*.deb
```

4. Verify:

```bash
ls /opt/nvidia/deepstream/deepstream/
gst-inspect-1.0 nvv4l2decoder     # Should list the plugin
```

## Swap File (Recommended)

8 GB of RAM is tight during builds. Add 4 GB of swap:

```bash
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

Verify: `free -h` should show ~4 GB swap.

## Remote Development

Most developers work on a desktop and test on the Jetson:

### Option 1: SSH + rsync

```bash
./scripts/deploy_jetson.sh una@<jetson-ip>
```

### Option 2: VSCode Remote-SSH

Install the VSCode Remote-SSH extension. Connect to the Jetson by hostname.
clangd will read `compile_commands.json` generated by the build.

### Option 3: Mount Jetson FS via sshfs

```bash
mkdir ~/jetson
sshfs una@<jetson-ip>:/home/una ~/jetson
# Now edit in your favorite IDE locally, build on the Jetson via SSH
```

## Camera Setup

The system is tested with:

- **USB cameras** (MJPEG-capable, e.g., Logitech C920, Arducam Global Shutter)
- **CSI cameras** (IMX219, IMX477 — require `nvarguscamerasrc` in the pipeline)
- **RTSP IP cameras** (H.264/H.265 — hardware-decoded by `nvv4l2decoder`)

To test USB cameras:

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video0 --list-formats-ext

# Quick preview
gst-launch-1.0 v4l2src device=/dev/video0 ! \
    "image/jpeg,width=1920,height=1080,framerate=30/1" ! \
    jpegdec ! videoconvert ! autovideosink
```

For RTSP:

```bash
gst-launch-1.0 rtspsrc location="rtsp://..." ! \
    rtph264depay ! h264parse ! nvv4l2decoder ! autovideosink
```

## Troubleshooting

**Build OOM** — reduce parallelism: `./scripts/build.sh Release -- -j2`

**Camera busy** — another process has `/dev/video0`. `fuser /dev/video0` shows which.

**"no suitable image found"** — wrong architecture for a pip package. Use aarch64 Python wheels.

**Display freezes when running** — Chromium/X11 may be competing for the GPU with TensorRT.
For kiosk use, switch to `nvdrmvideosink` (bypasses X11) in the pipeline.
